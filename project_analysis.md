# Анализ проекта Mini-Fight-prog — список доработок

## 1. Геймплей и механики

### 1.1. Баланс оружия
- **Проблема:** у оружия нет лимита Uses по умолчанию — в `Weapons.tres` отсутствует поле `Uses`. Uses подставляется из данных спавна волны, но если оружие создать вручную — сломается.
- **Нужно:** добавить поле `max_uses` в данные оружия (например, `Default_Sword` → `max_uses: 15`), использовать как значение по умолчанию.

### 1.2. Система эффектов на врагах — баги
- **`effect_connection()` в `base_enemy.gd`:** обращение к `CurrentEffects[0]` и `CurrentEffects[1]` — словарь не поддерживает числовые индексы. Нужно использовать `CurrentEffects.keys()[0]` / `CurrentEffects.keys()[1]`.
- **Комбинированные эффекты после соединения не удаляют исходные эффекты** — визуально висят обе иконки + комбинированная.
- **`current_combined_effect` не сбрасывается при завершении комбинированного эффекта** — враг перестаёт принимать новые эффекты навсегда.
- **Нет проверки на то, что в словаре >= 2 эффекта перед вызовом `effect_connection()`** — если вызвать с 1 эффектом, упадёт с ошибкой.

### 1.3. Система эффектов на врагах — доработки
- Эффекты не имеют визуального отображения на спрайте врага (подсветка огнём, частицы льда, зелёная аура яда).
- У врага нет анимации получения урона от тиков эффекта.
- При смерти врага эффекты не очищаются (визуально могут остаться на миг).

### 1.4. Комбинированные эффекты на оружии
- В `Weapons.tres` нет оружия, которое накладывает комбинированный эффект напрямую (например, "Fire+Ise_Sword" накладывает STEAM).
- Комбинированные эффекты определены в `Effect_connect.tres` — но нигде не используются в полной мере, т.к. наложение двух эффектов багнуто.

### 1.5. Система уклонения (додж/ролл)
- Рывок (dash) есть, но он не даёт неуязвимости (i-frames). Нет индикации неуязвимости (мерцание, прозрачность).
- Нет анимации рывка в 4+ направлениях — есть только анимация запуска, которая ждёт `animation_finished`, что может быть слишком долго.

### 1.6. Пауза
- **Отсутствует.** Невозможно поставить игру на паузу. Ни кнопки, ни хоткея.
- Нужно: UI паузы (затемнение + кнопки "Продолжить", "Выйти в меню"), обработка `ui_cancel` (Esc).

### 1.7. Хоткеи для слотов оружия (1-5)
- Есть инвентарь на 5 слотов, но в `in_game_ui.gd` нет подсветки текущего выбранного слота в Inventory (только в коде).
- Нет отображения номеров (1-5) над карточками оружия в UI.

### 1.8. Экран смерти/поражения
- При смерти игрока (`player.gd` → `die()`) игра просто проигрывает анимацию и всё — нет экрана "Game Over", нет рестарта, нет возврата в меню.
- **Нужно:** через секунду после смерти показывать UI с кнопками "Попробовать снова" / "Выйти в меню".

### 1.9. Экран победы
- После последней волны `LevelManager` испускает `LevelFinish` — но нет никакого визуального отклика (экран "Уровень пройден", анимация, переход на следующий уровень с подтверждением).

## 2. UI / UX

### 2.1. Главное меню
- Только кнопки "Start" и "Quit". **Нет:**
  - Кнопки "Настройки" — невозможно изменить громкость, разрешение, полноэкранный режим.
  - Кнопки "Выбор уровня" — сейв всегда идёт последовательно, нельзя перепройти старый уровень.
  - Подсказки управления.

### 2.2. HUD (InGame UI)
- **WavePanel:** показывает "Wave: 1/2" через анимацию, но не обновляется текст в процессе волны.
- **StaminaBar:** привязан к сигналу `SetStamina`, который **никогда не испускается** — ни в `player.gd`, ни где-либо ещё. Полоса выносливости всегда пустая/полная.
- **HealthBar:** работает корректно, но нет анимации получения урона (красная вспышка, тряска экрана).

### 2.3. Инвентарь / карточки оружия
- Нет подсказки при наведении на оружие на земле (tooltip "Нажмите E, чтобы подобрать").
- При подборе оружия нет визуального/звукового отклика — просто исчезает.
- Инвентарь не показывает эффект оружия (иконку огня/льда рядом с карточкой).

### 2.4. Миникарта
- Для уровней с большим количеством комнат нет миникарты — игрок легко теряется.

## 3. Звук и музыка

### 3.1. AudioManager — звуковые файлы отсутствуют
- В `AudioManager.gd` словарь `sounds` **пустой** — все строки с `preload()` закомментированы.
- Папки `sfx/` не существует в проекте.
- Нет звуковых файлов для: удара, подбора оружия, получения урона, смерти врага, шагов, рывка, смены оружия, UI-кликов, музыки уровней.

### 3.2. Система AudioManager не используется в коде
- Ни в `player.gd`, ни в `weapon.gd`, ни во врагах нет вызовов `AudioManager.PlaySFX.emit()`.
- Игра полностью безмолвна.

## 4. Противники (Enemies)

### 4.1. Orc
- При атаке влево анимация проигрывается только после установки `flip_h` — анимация рывка не всегда корректно отображается.
- Нет случайной вариации в поведении (все орки одинаковы).
- Нет визуальной индикации, какой тип атаки будет выполнен (Light / Heavy).

### 4.2. Mage
- Телепорт использует Casts (анимацию заклинания) для воспроизведения анимации телепорта, но она же используется для атак — возможна коллизия (начал кастовать атаку, потом телепорт с той же анимацией).
- Нет таймера между телепортами — маг может телепортироваться каждый кадр при высоком roll (>90 с 10% шансом каждый кадр в `_chase`).
- После смерти `Casts` останавливается, но не очищается последний кадр.

### 4.3. Chest (сундук-монстр)
- Открывается, но нет анимации открытия — мгновенный переход к атаке.
- Нет дропа (лута) после смерти.

### 4.4. Общие проблемы врагов
- Нет пула врагов — неиспользуемые враги не переиспользуются, а создаются и уничтожаются через `queue_free()` → возможны лаги при большом количестве спавнов.
- `navigation_agent` обновляет цель каждый кадр в `_chase` — избыточная нагрузка, достаточно обновлять раз в 0.1-0.2 сек.
- Нет разных типов атак с разной задержкой (кроме орка).

### 4.5. База данных врагов (Enemy.tres)
- У `Mage` `attack_range = 0` — маг никогда не переходит в состояние ATTACK через дистанцию (только через random roll в `_chase`).
- У `Mage` не заданы `spells` с правильной структурой — используется только Teleport, но код ожидает массив.

## 5. Оружие (Weapons)

### 5.1. Система атак
- У `weapon.gd` нет проверки перезарядки (cooldown) между атаками — игрок может атаковать каждый кадр, пока зажата кнопка.
- `attack()` в `weapon.gd` не проверяет, что `data` инициализирована — если вызвать до `set_weapon_data()`, будет ошибка обращения к `null` полю.

### 5.2. Типы оружия
- Только мечи. Нет: луков/арбалетов (дальний бой), посохов (магия), щитов (блок), метательного оружия.

### 5.3. Улучшение оружия
- Нет системы апгрейда — характеристики оружия фиксированы данными из `Weapons.tres`.

## 6. Система уровней

### 6.1. Несоответствие данных и сцен
- В `Levels.tres` уровни с 3 по 10 ссылаются на `res://data/levels/level_0X.tscn` (файлы сцен), а не на `res://scenes/arena/`. Скорее всего, этих файлов не существует — уровни 3-10 не запустятся.
- Для уровней 3-10 в `level_data` ссылаются на `res://data/levels/level_0X_data.tres` — эти файлы тоже отсутствуют.

### 6.2. LevelManager
- Флаг `debug_mode` выставляет `Current_level_id = 0` в `_ready()` — **всегда запускается тестовая арена**, игнорируя сохранённый прогресс.
- После `finish_level()` сейв увеличивает `level_id`, но нет проверки, что следующий уровень существует (выйдет за границы массива и упадёт).
- Нет возможности перезапустить текущий уровень без смерти / выхода.

### 6.3. SpawnManager
- У WeaponSpawners и EnemySpawners нет проверки, что ноды существуют — если на сцене нет `WeaponSpawners` или `EnemySpawners`, вылетит ошибка в `_ready()`.
- `WaveActivicy` — опечатка (Activity), используется как флаг окончания волны, но может остаться `true` если волна не размечена.

## 7. Технический долг

### 7.1. Код
- **`effect_connection()` в `base_enemy.gd`** — обращение к словарю по числовому индексу (см. п. 1.2).
- **`GlobalVar.gd`** — нет инициализации `Player = null`, при старте игры без спавна игрока обращение к `GlobalVar.Player` вернёт `null` и вызовет ошибку.
- **`player.gd`** — `current_health` использует `set` с вызовом GlobalVar сигнала, но `Max_Helth` (опечатка "Helth") не используется для вычислений — если изменить Max_Helth, health bar не обновится.
- **`base_enemy.gd`** — методы `_On_Ready`, `_on_die`, `_on_state_enter/exit` определены как пустые заглушки, хотя могли бы быть виртуальными. Это нормально для Godot, но нет вызова `.super()` в переопределениях — можно случайно сломать родительскую логику.

### 7.2. Ресурсы и данные
- **`Effects.tres`** содержит `"NONE"` эффект — бесполезная запись, т.к. NONE и так enum-значение.
- **`Effect_connect_data.tres`** — `EXPLOSION` имеет `Duration: 0.1` и `DamagePerTick: 20` — это одноразовый взрыв, но код в `base_enemy.gd` обрабатывает его как периодический эффект (тики). Взрыв должен нанести урон 1 раз и закончиться.
- **Нет файлов для уровней 3-10** — ни `.tscn`, ни `_data.tres`.

### 7.3. Пути и импорты
- Часть .tscn файлов использует старые uid-ссылки — при переименовании/перемещении ресурсов ссылки сломаются.
- В `scene_list.txt` некоторые файлы имеют дубликаты с `.tmp` расширением (например `Player.tscn19562613520.tmp`).

### 7.4. Конфигурация
- `window/size/viewport_width=480, viewport_height=270` — очень маленькое окно (пиксель-арт стиль). При scaling mode = integer на больших мониторах могут быть проблемы с отображением.
- Нет настроек управления (remapping клавиш).

## 8. Отсутствующие фичи (желательные)

### 8.1. Система опыта и прокачки
- Нет XP, уровней, перков, улучшений после волн.

### 8.2. Лутбоксы/дроп с врагов
- Враги не оставляют после смерти ничего — ни оружия, ни хилок, ни монет.

### 8.3. Магазин между волнами
- После волны можно было бы предложить выбор улучшения (roguelite-стиль).

### 8.4. Мультиплеер
- Локальный кооператив отсутствует (2-й игрок на геймпаде).

### 8.5. Сохранение прогресса
- Сохраняется только id текущего уровня. Нет сохранения: полученного оружия, характеристик, настроек громкости (Settings сохраняет, но UI для изменения нет).

### 8.6. Локализация
- Весь текст на русском в ресурсах, но нет системы локализации (Godot `tr()` не используется).
